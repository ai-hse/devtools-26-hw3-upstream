- В `scripts/` лежат заготовки для запуска, пакетной обработки, HTTP и резервного копирования. `run-container.sh` уже готов.

## Подготовка

Для задания нужна Linux-машина или Linux-ВМ с Bash, Python 3.12, `venv`, `curl`, `tar`, `ss`, `ps`, Docker Engine и плагином Docker Compose с поддержкой `up --wait`. Можно использовать учебную ВМ.

### Mac и Windows

На Mac установите [Multipass](https://documentation.ubuntu.com/multipass/latest/how-to-guides/install-multipass/install-multipass-on-macos/) и создайте Ubuntu в терминале Mac:

```bash
multipass launch 24.04 --name devtools --cpus 2 --memory 4G --disk 20G
multipass shell devtools
```

На Windows установите [WSL 2 с Ubuntu](https://learn.microsoft.com/windows/wsl/install/). Откройте терминал Ubuntu и проверьте, что используется WSL 2 командой `wsl -l -v` в PowerShell. Если Ubuntu уже установлена, выберите версию 24.04 с Python 3.12 или используйте учебную ВМ.

В обоих случаях установите [Docker Engine для Ubuntu](https://docs.docker.com/engine/install/ubuntu/) и плагин Compose внутри Ubuntu. Для запуска Docker без `sudo` настройте доступ пользователя по [инструкции Docker](https://docs.docker.com/engine/install/linux-postinstall/). При необходимости выйдите из Ubuntu и войдите снова. Клонируйте репозиторий в домашний каталог Ubuntu и выполняйте команды задания в её терминале. Для второго терминала снова откройте Ubuntu или выполните `multipass shell devtools` на Mac.

Docker Desktop запускает контейнеры в отдельной Linux-среде. В этом задании часть опытов сравнивает контейнер с Linux-хостом, поэтому Docker Engine и команды должны работать в одной Linux-среде.

### Проверить окружение

Если программы ещё не установлены, воспользуйтесь инструкциями по [Python](https://docs.python.org/3.12/using/unix.html), [Docker Engine](https://docs.docker.com/engine/install/) и [плагину Compose](https://docs.docker.com/compose/install/linux/). Проверьте `python3 --version`, `docker info` и `docker compose version`. Команда `python3` должна запускать Python 3.12, а Docker – быть доступен вашему пользователю.

В Ubuntu 24.04 для создания виртуального окружения может понадобиться пакет `python3.12-venv`. Установите его командой `sudo apt install python3.12-venv`.

Во всех частях команды выполняются **на этой Linux-машине, из корня проекта**, если шаг явно не указывает другое место. Для HTTP-запросов к работающему серверу понадобится второй терминал.

Локальные Bash-скрипты получают настройки через переменные окружения. Читать `.env` в этих скриптах не требуется. Для Compose в части 6 используется локальный `.env`.

1. Склонируйте свой репозиторий и создайте ветку `solution` от `main`.
2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   ```

3. Прочитайте справку двух точек входа. Формат CSV и пример результата также есть в [справке готового приложения](../interfaces.md):

   ```bash
   .venv/bin/python app/analyzer.py --help
   .venv/bin/python app/server.py --help
   ```

4. Подготовьте каталоги для результатов и обработайте первый файл:

   ```bash
   mkdir -p work/reports work/logs
   .venv/bin/python app/analyzer.py samples/clean.csv --output work/reports/clean.json
   ```

Откройте CSV и отчёт. Каждая строка CSV описывает один эксперимент. В числовых столбцах указаны его метрики. Сопоставьте число строк и хотя бы одну статистику с исходными данными. Это пример результата, который позже будет создавать автоматизация.

Добавьте в `.gitignore` окружение, рабочие данные, логи, архивы, локальный `.env` и кеш Python (`__pycache__`, `*.pyc`). Подготовленные примеры из `samples/` должны остаться в Git.

**Границы задания.** Проверки используют небольшие CSV и архивы. Параллельные запуски скриптов не проверяются. Не проверяются также одновременная запись в каталог резервной копии и изменение прав во время работы. Веб-сервер работает одним процессом. Его архитектуру менять не нужно.

**Общие требования к скриптам.** Пишите скрипты на Bash и запускайте их через `bash`, как в примерах. Скрипты должны принимать пути с пробелами и запускаться из другого каталога. Относительные пути в аргументах отсчитываются от каталога, из которого вызвали скрипт. Путь к проекту скрипт определяет отдельно. При неверном числе аргументов скрипт возвращает ненулевой код и пишет сообщение в stderr. Точные коды возврата указаны в соответствующих частях.

**Опыты.** Сформулируйте прогноз, измените одно условие и сравните результат. Объясните себе, почему поведение изменилось.

**Подготовка завершена:** виртуальное окружение создано, анализатор выдал первый отчёт. Запущенных серверов пока нет. Удачи!
