# Часть 1. Исправить запуск • 1 балл

Коллеги хотят запускать сервис из любого каталога, а `scripts/start.sh` пока не запускается даже из корня проекта. Исправьте `scripts/start.sh`. Настройки запуска уже есть в `app/settings.py`.

Выполните из корня проекта:

```bash
bash scripts/start.sh
```

Прочитайте ошибку и найдите её причину. Затем исправьте запуск по требованиям ниже.

## 1.1. Требования к запуску

- `start.sh` находит проект и его `.venv`, из какого бы каталога его ни вызвали. Абсолютный путь своей машины в исходники не записывайте.
- `HOST`, `PORT` и `DATA_DIR` передаются через окружение. По умолчанию: `127.0.0.1`, `8080` и каталог `work/data` внутри проекта.
- В `DATA_DIR` передаётся абсолютный путь. В нём могут быть пробелы.
- Журнал загрузок и отчёты сервис хранит внутри `DATA_DIR`. Если каталога нет, он создаётся при запуске.
- Если окружения Python нет или в `DATA_DIR` нельзя писать, запуск завершается с ненулевым кодом и понятным сообщением в stderr.
- Зависимости при каждом запуске не устанавливаются.
- Сервер работает на переднем плане (foreground): терминал занят, пока сервер не остановят. После `Ctrl+C` процесс завершается и порт освобождается.

## 1.2. Проверить

Запустите сервер с параметрами:

```bash
HOST=127.0.0.1 PORT=8080 DATA_DIR="$PWD/work/data" bash scripts/start.sh
```

Во втором терминале выполните:

```bash
curl -i http://127.0.0.1:8080/health
```

Ожидается HTTP 200 и JSON со статусом `ok` и версией приложения.

Нажмите `Ctrl+C` и убедитесь, что порт освободился. Запустите сервер **из другого каталога**, сменив порт и указав путь к данным с пробелом:

```bash
(cd /tmp && PORT=8081 DATA_DIR="/tmp/csv data" bash "$OLDPWD/scripts/start.sh")
```

> **На подумать.** Куда указывает относительный путь, если запустить скрипт из другого каталога?
