# Часть 1. Исправить запуск • 1 балл

Коллеги хотят запускать сервис из любого каталога, а `scripts/start.sh` пока не запускается даже из корня проекта. Исправьте `scripts/start.sh`. Настройки запуска уже есть в `app/settings.py`.

Выполните из корня проекта:

```bash
bash scripts/start.sh
```

Прочитайте ошибку и найдите её причину. Затем исправьте запуск по требованиям ниже.

## 1.1. Требования к запуску

- `start.sh` сам находит `.venv` проекта и запускает сервер из любого каталога без переустановки зависимостей.
- Сервер читает `HOST`, `PORT` и `DATA_DIR` из окружения. По умолчанию он слушает `127.0.0.1:8080` и пишет данные в `work/data` внутри проекта.
- Если задан `DATA_DIR`, это абсолютный путь, в котором могут быть пробелы. При запуске сервис создаёт недостающий каталог и хранит в нём отчёты и журнал загрузок.
- Если нет `.venv` или сервис не может писать в каталог данных, запуск завершается с ненулевым кодом и объяснением в `stderr`.
- Сервер занимает терминал до остановки. По `Ctrl+C` он завершается и освобождает порт.

## 1.2. Проверить

Запустите сервер с параметрами:

```bash
HOST=127.0.0.1 PORT=8080 DATA_DIR="$PWD/work/data" bash scripts/start.sh
```

Во втором терминале выполните:

```bash
curl -i http://127.0.0.1:8080/health
```

Ожидается HTTP 200 и JSON со статусом `ok` и версией приложения.

В терминале с сервером нажмите `Ctrl+C` и убедитесь, что порт освободился. Запустите сервер **из другого каталога**, сменив порт и указав путь к данным с пробелом:

```bash
(cd /tmp && PORT=8081 DATA_DIR="/tmp/csv data" bash "$OLDPWD/scripts/start.sh")
```

> **На подумать.** Куда указывает относительный путь, если запустить скрипт из другого каталога?
