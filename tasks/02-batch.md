# Часть 2. Обработать каталог файлов • 1,5 балла

Коллеги прислали каталог с результатами. Один CSV в нём повреждён, остальные нужны для отчёта. Доработайте `scripts/batch.sh`: он должен обработать весь каталог и показать, что случилось с каждым файлом. Сервер в этой части не нужен, примеры лежат в `samples/batch`.

```bash
bash scripts/batch.sh samples/batch work/batch-reports work/batch-logs
```

Аргументы по порядку: входной каталог, каталог отчётов и каталог логов. Каждый файл обрабатывайте готовым `analyzer.py`. Если каталогов отчётов и логов нет, скрипт их создаёт.

В проверках входные данные, отчёты и логи лежат по разным путям. Имена могут содержать пробелы и кириллицу. Скрытых CSV, переносов строк в именах и имён, начинающихся с `-`, не будет.

## 2.1. Обработать каталог • 0,75 балла

**Требования:**

- Скрипт обрабатывает обычные файлы `.csv`, лежащие прямо во входном каталоге. Подкаталоги и символические ссылки пропускаются.
- Для `run 01.csv` отчёт сохраняется как `run 01.json`, а stderr анализатора как `run 01.log`. Если ошибок нет, лог остаётся пустым.
- Повреждённый файл не останавливает обработку остальных.

Например, для двух файлов результат будет таким:

| Входной каталог | Каталог отчётов | Каталог логов |
|---|---|---|
| `run 01.csv` | `run 01.json` | `run 01.log`, пустой |
| `broken.csv`, повреждён | отчёта нет | `broken.log` с ошибкой |

Запустите скрипт на примерах. Среди них есть файлы с пробелом и кириллицей в имени. Убедитесь, что для каждого корректного CSV появился JSON.

## 2.2. Ошибки, повторный запуск и логи • 0,75 балла

### Какой код вернёт конвейер с `tee`?

1. Сравните код завершения анализатора для корректного и повреждённого CSV.

2. Запустите отдельную оболочку `bash` и в ней передайте stderr ошибочного запуска через `tee` в лог.

3. Сравните код завершения анализатора с кодом всего конвейера.

**Требования:**

- Если в скрипте есть конвейер, признак ошибки в нём не теряется.
- Последняя строка stdout скрипта содержит число успешных и неуспешных обработок. Для двух успешных файлов и одного повреждённого она выглядит так:

  ```text
  processed=2 failed=1
  ```

- Коды завершения:

  | Код | Когда |
  |---|---|
  | `0` | Все найденные CSV обработаны |
  | `1` | Хотя бы один файл обработан с ошибкой |
  | `2` | Неверные аргументы, входного каталога нет, в нём нет ни одного CSV или не удалось подготовить каталоги результатов. Укажите причину в stderr. Строка счётчиков не нужна |

### Что останется от прошлого запуска?

Скопируйте `samples/clean.csv` в отдельный каталог и запустите для этого каталога `batch.sh`. В копии замените одно число словом и повторите ту же команду. Что теперь в `clean.log`? Остался ли в каталоге отчётов прежний `clean.json`?

**Требования:**

- При повторном запуске скрипт заменяет отчёты и логи файлов, которые обрабатывает.
- Если файл повреждён, его старый отчёт удаляется.
- Посторонние файлы в каталогах результатов скрипт не трогает.
