# ДЗ 3. Подготовить CSV-сервис к запуску

Небольшая команда хранит результаты измерений в CSV-файлах, а сервис строит по ним отчёты. CSV (Comma-Separated Values) – текстовый формат таблиц, в котором значения разделены запятыми. Сам сервис работает, но всё вокруг него сломано: `start.sh` не запускается, пакетная обработка не замечает повреждённые файлы, а после замены контейнера пропадают отчёты.

Анализатор и сервер уже готовы. Вы почините скрипты, упакуете сервис в Docker и соберёте его вместе со шлюзом в Compose. В итоге сервис поднимается одной командой, отвечает на `/health`, принимает CSV и сохраняет отчёты после пересоздания контейнеров.

Каждый критерий засчитывается целиком или не засчитывается совсем. Грейдер запускает скрытые тесты на других данных, но проверяет только требования из текста заданий.

Для тех, кому интересно разобраться глубже, есть [дополнительные вопросы](experiments.md).

## Сдача

1. Проверьте, что сервис запускается через Compose, отвечает на `/health`, принимает CSV и сохраняет отчёты после пересоздания контейнеров.

2. Закоммитьте решение в ветку `solution`. В коммит входят скрипты, настройки, `Dockerfile`, `compose.yaml`, конфигурация шлюза и ignore-файлы. Примеры CSV и приложение остаются в репозитории. Рабочие отчёты, архивы, `.env` и `.venv` не добавляйте.

3. Запустите проверку готовности:

   ```bash
   bash tools/check-ready.sh
   ```

   Она проверяет ветку, файлы, чистоту рабочего каталога и конфигурацию Compose. Правильность решения она не проверяет.

4. Отправьте ветку:

   ```bash
   git push -u origin solution
   ```

5. Откройте PR из `solution` в `main`.

Грейдер проверит решение, запишет результат в Issue «Автопроверка HW3» и закроет PR без слияния. Чтобы сдать заново, откройте новый PR. Всего 10 попыток, как в ДЗ 2. Попытка тратится, только если грейдер выставил балл.
