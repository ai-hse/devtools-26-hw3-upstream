# ДЗ 3. Подготовить CSV-сервис к запуску

**Дедлайн: хх.хх.26 23:59 (GMT+3)**

Небольшая команда хранит результаты измерений в CSV-файлах, а сервис строит по ним отчёты. Сам сервис работает, но всё вокруг него сломано: `start.sh` не запускается, пакетная обработка не замечает повреждённые файлы, а после замены контейнера пропадают отчёты.

Код приложения менять не нужно. Вы почините скрипты, упакуете сервис в Docker и соберёте его вместе со шлюзом в Compose. В итоге сервис поднимается одной командой, отвечает на `/health`, принимает CSV и сохраняет отчёты после пересоздания контейнеров.

Каждый критерий засчитывается целиком или не засчитывается совсем. Грейдер запускает скрытые тесты на других данных, но проверяет только требования из текста заданий.

Форматы CSV и HTTP описаны в [справке](interfaces.md). Необязательные опыты для тех, кому интересно копнуть глубже, собраны в [experiments.md](experiments.md).

## Обновление задания

Условия и исправления появляются в общем репозитории. Один раз добавьте его в свой клон:

```bash
git remote add upstream https://github.com/ai-hse/devtools-26-hw3-upstream.git
```

Перед началом работы и после объявления об обновлении выполните в ветке `solution` команду ниже. Если есть незакоммиченные изменения, сначала сохраните их в коммит:

```bash
git pull --no-rebase --no-edit upstream main
```

Если Git сообщает о конфликте, разрешите его и завершите слияние. Решение остаётся в вашей ветке. Доступ к общему репозиторию выдаётся вместе с заданием.

## Сдача

1. Проверьте, что сервис запускается через Compose, отвечает на `/health`, принимает CSV и сохраняет отчёты после пересоздания контейнеров.

2. Закоммитьте решение в ветку `solution`. В коммит входят скрипты, настройки, `Dockerfile`, `compose.yaml`, конфигурация шлюза и ignore-файлы. Примеры CSV и приложение остаются в репозитории. Рабочие отчёты, архивы, `.env` и `.venv` не добавляйте.

3. Запустите проверку готовности:

   ```bash
   bash tools/check-ready.sh
   ```

   Она проверяет ветку, файлы, чистоту рабочего каталога и конфигурацию Compose. Правильность решения она не проверяет.

4. Отправьте ветку:

   ```bash
   git push -u origin solution
   ```

5. Откройте PR из `solution` в `main`.

Грейдер проверит решение, запишет результат в Issue «Автопроверка HW3» и закроет PR без слияния. Чтобы сдать заново, откройте новый PR. Всего 10 попыток, как в ДЗ 2. Попытка тратится, только если грейдер выставил балл.
